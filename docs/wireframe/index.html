컴포넌트

#컴포넌트설명 · 제약
1SearchBar플레이스홀더 “앱 이름이나 키워드를 검색해 보세요”. 키보드 리턴 키 .search. 최대 100자 (서버 제한과 동일).
2섹션 헤더“최근 검색어”. 목록이 비면 헤더 자체를 숨김.
3전체 삭제탭 즉시 전체 삭제 (확인 없이). 설정 화면의 전체 삭제는 확인 다이얼로그 있음 (p.14).
4최근 검색어 행탭 → 검색어를 입력창에 채우고 즉시 검색 (디바운스 없이) + 검색 시각 갱신.
5개별 삭제 ✕44pt 터치 영역. 삭제 후 목록은 DB 관찰로 자동 갱신.
6빈 상태최근 검색어가 0개이고 검색어가 비어 있을 때.

제약사항

  • 최대 10개, 최신순
  • 대소문자·앞뒤 공백이 달라도 같은 검색어 (“Kakao ” = “kakao”) → 맨 위로 이동, 표기는 마지막 입력값
  • 검색어 저장 시점: 제출(리턴 키) 또는 최근 검색어 탭. 디바운스 자동 검색은 저장하지 않음
  • 공백뿐인 검색어는 저장·검색하지 않음

TCA 제안

  • onAppear(.task)에서 recentKeywordUseCase.observe() 구독 → recentKeywordsUpdated([RecentKeyword])
  • recentKeywordTapped(RecentKeyword)
  • recentKeywordDeleteTapped(id:)
  • clearRecentKeywordsTapped
  • 구독 Effect는 .cancellable(id: CancelID.recentKeywords)
테스트 포인트 · 구독 중 DB가 바뀌면 State가 갱신되는지 (TestStore + 가짜 스트림), 최근 검색어 탭 시 저장과 검색이 함께 일어나는지.

C. 결과
#컴포넌트설명 · 제약
1입력 → 자동 검색글자가 바뀔 때마다 300ms 디바운스 후 검색. 대기 중에는 이전 화면(최근 검색어 또는 이전 결과)을 그대로 보여 줌.
2✕ 지우기검색어·결과·에러를 모두 비우고 최근 검색어 화면(p.4)으로. 진행 중인 요청 취소.
3첫 로딩결과가 없을 때만 가운데 스피너 “검색 중…”. 이전 결과가 있으면 결과를 유지한 채 다시 불러옴.
4결과 개수서버 total 사용. “검색 결과 N개”.
5결과 셀셀 구성·페이지네이션은 p.7. 탭 → 상세 push (p.8).

제약사항

  • 디바운스 300ms (continuousClock 주입 → 테스트에서 TestClock)
  • 새 검색이 시작되면 이전 요청 취소 (cancelInFlight: true) → 늦게 온 이전 응답이 결과를 덮지 않음
  • 리턴 키 제출: 디바운스 무시하고 즉시 검색 + 최근 검색어 저장
  • 검색어가 공백뿐이면 요청하지 않고 p.4 상태
  • 페이지 크기 20

TCA 제안

  • BindableAction + $store.query 또는 queryChanged(String)
  • searchSubmitted
  • searchResponse(Result<Page<AppSummary>, any Error>)
  • clearButtonTapped
  • State: query, results: IdentifiedArrayOf<AppSummary>, total, nextPage: PageRequest?, isLoading
테스트 포인트 · TestClock으로 299ms에는 요청이 없고 300ms에 한 번만 요청되는지, 빠르게 두 번 입력하면 마지막 검색어만 요청되는지.

B. 에러 (결과 없음 상태)
#컴포넌트설명 · 제약
1결과 없음제목 “‘{검색어}’ 검색 결과가 없어요”, 설명 “철자를 확인하거나 다른 키워드로 검색해 보세요.” 검색어가 길면 제목 2줄까지 후 말줄임.
2에러 화면결과가 하나도 없을 때의 실패만 화면으로 표시. 메시지는 DomainError.message 그대로.
3다시 시도같은 검색어·같은 페이지로 재요청. 누르면 B → 로딩(p.5-B).

에러별 문구 (DomainError.message)

케이스문구발생
.network네트워크 연결을 확인해 주세요.오프라인·타임아웃
.server(message)서버 메시지 또는 “서버에 문제가 생겼어요. 잠시 후 다시 시도해 주세요.”5xx
.validation서버 검증 메시지 (예: 요청 값이 올바르지 않아요.)4xx 입력 오류
.unknown알 수 없는 문제가 발생했어요.디코딩 실패 등
CancellationError표시하지 않음새 검색으로 이전 요청이 취소됨

규칙

  • 결과가 이미 있는 상태에서 다음 페이지 실패 → 화면 전체 에러가 아니라 목록 하단 재시도 (p.7)
  • 에러 상태에서 검색어를 바꾸면 에러를 지우고 새로 검색
  • 취소(CancellationError)는 에러로 취급하지 않음

TCA 제안

  • State: loadState: enum { idle, loading, loaded, empty, failed(String) } 처럼 한 값으로 표현하면 모순 상태(로딩 중인데 에러)가 생기지 않음
  • retryButtonTapped

항목규칙
제목무엇이 실패했는지: “저장하지 못했어요”, “사진을 바꾸지 못했어요”, “삭제하지 못했어요”
메시지DomainError.message 그대로 (사용자용 문장으로 이미 작성됨)
버튼“확인” 하나. 재시도 버튼은 넣지 않음 (화면의 버튼으로 다시 시도)
공통화AlertState.error(title:message:) 같은 extension을 Feature 공용 위치에 두고 재사용 (강의 코드처럼 화면마다 복붙 금지)
닫기.ifLet(\.$alert, action: \.alert)가 자동 처리 → case .dismiss: state.alert = nil 작성 불필요
